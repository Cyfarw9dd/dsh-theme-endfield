# 设计语言

本文是这套主题的设计说明：**颜色是什么、为什么是这个值、落在哪个界面角色上**。想拿它当设计语言学习入口的，读这一篇就够。

工程实现细节在 [engineering-notes.md](engineering-notes.md)，测试在 [testing.md](testing.md)。

---

## 一、核心概念：工业编辑风

终末地官网的视觉不是「深色科技感」，而是**印刷编辑风**：一张有质感的纸、压在上面的墨黑字、以及一个用来做信号的高饱和色。三条规则贯穿全篇：

1. **纸与墨是主体，强调色是信号。** 强调色只用于「需要被看见的那一处」——按钮、悬停、选中行、焦点环——而不是大面积铺色。
2. **全直角。** 圆角会把界面推向「柔和产品」的观感；直角把它推向「技术文档 / 工程图纸」。只有形状本身是圆的（状态点、头像、加载圈）才保留圆形。
3. **数字等宽。** 开启 `tnum`，让表格、耗时、百分比在跳动时不产生横向抖动。

## 二、色板

### 中性色（纸 / 墨 / 线）

两套模式共用同一套语义，只换取值。

| 角色 | 令牌 | 亮色 | 暗色 |
| --- | --- | --- | --- |
| 纸底（应用背景、侧栏） | `--dsw-alias-bg-base` | `#e8e8e2` | `#101110` |
| 面板 / 气泡 | `--dsw-alias-bg-layer-1` | `#f2f2ec` | `#181a18` |
| 沉底块 | `--dsw-alias-bg-layer-2` | `#dcddd6` | `#1e201d` |
| 浮层（菜单、弹层） | `--dsw-alias-bg-overlay` | `#f2f2ec` | `#1c1e1c` |
| 细线 | `--dsw-alias-border-l1` | `#d8d9d5` | `#343633` |
| 重线 | `--dsw-alias-border-l2` | `#b6b8b3` | `#4a4d49` |
| 正文 | `--dsw-alias-label-primary` | `#101110` | `#f5f5f0` |
| 次要文字 | `--dsw-alias-label-secondary` | `#4a4c48` | `#898d89` |

亮色不用纯白 `#fff`、暗色不用纯黑 `#000`：`#e8e8e2` 带一点暖灰，是「纸」而不是「屏幕」；`#101110` 留一点绿倾向，避免深灰界面常见的死黑。

### 强调色：三套配色

设置页「主题配色」在三者间循环，**默认终末地灰**。

| 配色 | 强调色 | 相对亮度 | 说明 |
| --- | --- | --- | --- |
| **终末地灰**（默认） | 亮 `#d9d9d9` / 暗 `#6a6a6a` | 68.7% / 15.4% | 官网交互灰阶：悬停/选中用灰，黄只是信号 |
| **谷地黄** | `#fff500` | 86.6% | 终末地官网的信号黄 |
| **武陵青** | `#14d0d0` | 49.8% | 青碧色 |

存储字段 `palette`（UI/存储键 `dsh-theme-endfield-palette`，由 `PREFS_KEY_TO_FIELD` 映射），取值 `gray` / `valley` / `wuling`。未设置或异常值回落到默认 `gray`；只有精确值 `valley` / `wuling` 选中亮色配色。

#### 终末地灰的来源与「填充/文字」分离

灰阶取值直接量自官网发布 CSS（endfield.hypergryph.com 的官方 bundle）：暗色按钮悬停 `#484848`、列表悬停 `#626262`、亮色悬停 `#f0f0f0` / `#d9d9d9`——**官网的悬停/选中全是灰阶，黄只留给主 CTA 与选中标记**。官网 CSS 颜色统计也印证：`#191919`（85 次）遥遥领先，`#fffa00`（57 次）只是稀有信号。

纯灰有一个数学事实：在近黑底上没有任何一个灰能同时满足「底上白字 AA」与「灰作文字 AA」（两条亮度区间不相交）。所以灰配色把两个角色拆到架构已有的两组变量上：

- `--edge-accent` / `--edge-accent-deep`：只作**填充**，配对新令牌 `--edge-accent-ink`（亮色墨字、暗色白字）；
- `--edge-status-dark` / `-mid`：暗色「强调作文字」角色（`#d9d9d9` / `#b3b3b3`）。

亮黄/青配色里 status-dark == accent，所以这个拆分对它们是零视觉变化的。所有「强调底 + 硬编码黑字」的规则（`::selection`、选中行、徽章悬停、新会话按钮等约 20 处）都改为读 `--edge-accent-ink`。暗色填充取 `#6a6a6a`（官网 `#666`–`#7e7e7e` 家族）：是同时通过两张暗色底 3:1 非文本下限（焦点环/光标/滚动条直接读 accent）的最深一档。

## 三、强调色的派生角色

一个强调色不够用。同一个色在不同表面上需要不同的取值，这些派生量在样式表里都是 CSS 变量，**声明在 `body` 上**（原因见[工程笔记](engineering-notes.md#变量必须声明在-body-而不是-root)）。

| 变量 | 谷地黄 | 武陵青 | 终末地灰（亮/暗） | 用途 |
| --- | --- | --- | --- | --- |
| `--edge-accent` | `#fff500` | `#14d0d0` | `#d9d9d9` / `#6a6a6a` | 实心底、图标、焦点环、光标 |
| `--edge-accent-ink` | `#101110` | `#101110` | `#101110` / `#ffffff` | 强调底上的文字（`::selection` 等） |
| `--edge-accent-rgb` | `255, 245, 0` | `20, 208, 208` | `126, 126, 126` | 约 30 处 `rgba(var(--edge-accent-rgb), α)` 半透明色块 |
| `--edge-accent-deep` | `#e8e000` | `#10b8b8` | `#cccccc` / `#424242` | 悬停 / 按下加深 |
| `--edge-accent-onpaper` | `#d9c700` | `#14d0d0` | `#666666` / `#6a6a6a` | 亮色模式下唯一需要「作填充压在纸上」的槽位 |
| `--edge-status-light` | `#6b5d00` | `#006a6a` | `#666666` | 亮色模式回合状态文字 |
| `--edge-status-light-mid` | `#3f3600` | `#003f3f` | `#4a4a4a` | 亮色模式流光亮带 |
| `--edge-status-dark` | `#fff500` | `#14d0d0` | `#d9d9d9` | 暗色模式回合状态文字（灰配色兼作「强调作文字」角色） |
| `--edge-status-dark-mid` | `#a08a00` | `#7ee7e7` | `#b3b3b3` | 暗色模式流光亮带 |
| `--edge-glow-light` | `0.08` | `0.08` | `0.08` | hero 背景光晕透明度 |
| `--edge-glow-dark` | `0.05` | `0.04` | `0.04` | 同上，暗色 |

### 为什么亮色模式的强调色要「下沉」

这是最容易踩的一条。**在奶油纸底上，`#fff500` 不是一种配色选择，而是一次抹除**——黄色文字压在纸底上只有 1.07:1（面板 `#f2f2ec` 上更低，1.02:1），完全不可见。同理青色也过不了：`#14d0d0` 在纸底上仅 1.56:1。

所以亮色模式里凡是「强调色作为文字」的地方，都换成同一色相的**深色档**：

- 谷地黄 → `#6b5d00`（5.35:1，亮色下第一个达标的金）
- 武陵青 → `#006a6a`（5.22:1）

在纸上，`#007070` 以上的青都过不了双底 AA——这是**纸的属性**，不是强调色亮度的问题，所以武陵青提亮后这两个值完全没变。

而暗色模式方向相反：底是近黑，强调色本身就够亮，直接用原色。

### 为什么暗色的「亮带」方向不一致

回合状态标签是渐变流光文字，中间有一条亮带扫过字形。

- 谷地黄的亮带是**压暗**的 `#a08a00`——黄色向上已经到顶，再亮就成白色。
- 武陵青的亮带是**提亮**的 `#7ee7e7`——青色在这个亮度向下的余量比黄色小，更深的青（`#0a7d7d`）只有 3.54:1 不达标。

同一个规则（AA 4.5:1），两个相反的方向。这类「不能照抄」的地方是本主题最主要的复杂度来源。

### 武陵青为什么是 `#14d0d0`

初版用了 `#0daaaa`，相对亮度只有 31.7%——不到谷地黄（86.6%）的四成，在近黑页面上存在感明显弱一截。`#14d0d0` 保持同一条色轴（R 低、G = B，仍是青碧而非灰青），亮度提高到 49.8%。

上界同样有约束：到 `#16dcdc` 时，亮色模式下色块与纸底只剩 1.39:1（现行 1.56:1），开始「融进纸里」，而且那么浅的青读起来偏白。**`#14d0d0` 是两种模式下都还站得住的最亮一档。**

这两条边界写成了断言（亮度下限 45%、上限 56%、必须留在青碧色轴上）。

## 四、对比度规则

**每个角色都要对它实际落在的表面验算，不达标就构建失败。** `test/palette-contrast.test.js` 覆盖全部 27 项。

| 角色 | 谷地黄 | 武陵青 | 门槛 |
| --- | --- | --- | --- |
| 实心强调底 + 墨色字 | 16.50:1 | 9.88:1 | AA 4.5 |
| 悬停加深底 + 墨色字 | 13.60:1 | 7.72:1 | AA 4.5 |
| 暗色图标 / 链接强调色 | 15.26:1 | 9.14:1 | ≥3 |
| 回合状态·亮色主色 | 5.35:1 | 5.22:1 | AA 4.5 |
| 回合状态·亮色亮带 | 9.82:1 | 9.58:1 | AA 4.5 |
| 回合状态·暗色主色 | 15.26:1 | 9.14:1 | AA 4.5 |
| 回合状态·暗色亮带 | 5.11:1 | 12.06:1 | AA 4.5 |

三条附加规则：

- **渐变文字要对两种底色都达标**（`bg-base` 与 `bg-layer-1`），因为亮带会扫过字形；而在 `prefers-reduced-motion` 下上游把 `background-size` 钉成 100%，那条亮带会**永久留在**字里。
- **相同 alpha ≠ 相同存在感**：半透明面按「合成后对比度对齐」分别调参，而不是照抄。
- **hero 光晕只许更轻，不许更响**：判据是单侧的——比它替换的 `#6187D8` @8% 更安静永远可接受。

> **装饰性表面的对比度描述的是「有多抢眼」，不是可读性。** 水印永远在正文之后，它的对比度数值用来控制干扰强度。经验下限约 `1.06:1`，低于此形同不存在。
>
> **水印是工业徽标的矢量单标**：[Yue-plus/endfield_icons](https://github.com/Yue-plus/endfield_icons) 对官方 Hypergryph 徽标（条码字标 + 倒三角）的矢量重制版，构建时剥离编辑器元数据后以 SVG data URI 内嵌为 CSS mask（`assets/endfield-industries.svg`，来源与 sha256 见 `scripts/build-emblem.js` 头注；采用该第三方来源已经仓库所有者显式批准）。**alpha 模式** mask：path 自身的 alpha 通道就是形状，默认黑填充即可用 `currentColor` 上色，亮暗两模式自动适配；矢量意味着任何缩放与 DPR 下都硬边清晰（此前的官方位图掩码受 755px 源图上限约束）。水印不含任何文字（ENDEFIELD 大字已移除），翻译器无从改写。声明必须在 `body { }` 规则内——顶层裸声明会让 CSS 解析器吞掉下一条规则的选择器（已用 check.js 断言钉死）。

## 五、令牌映射：中和残留品牌蓝

DSH 自带 DeepSeek 品牌蓝。主题把这些令牌整组重映射，否则会在纸墨界面里留下零散的蓝点。

| 令牌组 | 处理 |
| --- | --- |
| `--dsw-static-deepseek-50…900` | 整组换成中性灰阶（亮色为纸阶，暗色为墨阶） |
| `--dsw-static-deepseek-450` | 亮色 → `--edge-accent-onpaper`，暗色 → `--edge-accent` |
| `--dsw-static-deepseek-500/600` | → 墨 / 纸色（**不可动**，见下） |
| `--dsw-alias-button-info-fill` | 亮色 → 墨黑，暗色 → 强调色 |
| `--dsw-alias-state-business-primary` | 同上 |
| `--dsw-specific-sidebar-nav-item-active-accent` | 同上 |
| `--dsw-alias-label-primary-bluish` | → 正文色 |
| `--dsw-specific-bubble` / `-highlight` | → 面板 / 沉底块 |

`--dsw-static-deepseek-500/200` 是**共享令牌**：同时支撑 `button-info-fill`、`state-business-primary` 与 `bubble-highlight`。要改回合状态标签的颜色时不能动它们，只能覆盖那条规则自己的 `background-image`。

### 强调色交互一览

| 表面 | 声明 |
| --- | --- |
| 文本选中 | `::selection` 用**不随调色板的官网交互灰**：亮 `#d9d9d9`+墨字 / 暗 `#6a6a6a`+白字（官网语法：选中走灰阶，强调色只做信号） |
| 输入光标 | `caret-color: var(--edge-caret)`，同为固定灰：亮 `#666666` / 暗 `#d9d9d9` |
| 焦点环 | `outline: 2px solid var(--edge-accent)`，`offset: 1px` |
| 滚动条 | 轨道透明，滑块 `--edge-line`，悬停 `--edge-accent` |
| 链接悬停 | 下划线着色；暗色模式下文字也变强调色 |
| 表格行悬停 | 实心强调底 + 墨色字 |
| 半透明色块 | `rgba(var(--edge-accent-rgb), α)`，亮色 α 略低于暗色 |

亮色与暗色的 α 不同：**在近黑底上叠加亮度，比在纸底上减去亮度显得响得多**。同一个 α 在暗色下更吵，所以暗色的半透明块普遍取更高的 α（因为强调色本身在暗色下要更突出），而装饰性图层（水印）在暗色下反而要**降低** α。

### 交互动效：合并设计

> 2026-10 起动效是**一套固定设计**，由 `<body>` 属性 `data-endfield-motion` 的在场/缺席开关。它由六套可切换方案合并而来（用户决定）：**B 静默、C 冲压、F 盖章整体移除**，E 读数随主 CTA 归属信号而失去独立母题，两套幸存母题按角色分工——**信号**（新会话/审批按钮箭头滑入、表格行左缘细条）与**角标**（侧边栏会话行 + 搜索结果行四角 L 形角标）。共通底座：全局 `.2s` 颜色过渡 + 按下暗一档。

下表是**合并前**的六套方案（留作决策档案：为什么删、留了什么，都能对回这张表）：

| 方案 | 母题 | 主要落点 | 悬停 | 按下 | 合并后 |
| --- | --- | --- | --- | --- |
| **A signal** | 官网签名 | 新会话 / 审批 | 信号色箭头自左侧滑入（**不做悬停圆角软化**，见下） | 底色暗一档 | **保留**（+表格行左缘细条） |
| **B silent** | 极简 | 全部 | 只有 `.2s` 颜色过渡 | 底色暗一档 | 移除（其「共通底座」本就是每套方案的一部分） |
| **C impact** | 冲压 | 全部 | 硬阴影 4px→2px（**官网用的是软阴影，4px 硬阴影是主题推导**）、左缘信号边条 | 位移 2px 压进纸面 | 移除（位移推挤相邻元素，与官网「变形优先于位移」相抵触） |
| **D clamp** | 工程标注 | 普通按钮 / 列表行 / 主 CTA | 四角 12px L 形角标淡入（`.18s`，只动 opacity）；CTA 加左缘边条 + 文字横移 2px | 底色暗一档 | **母题保留、落点收窄**：角标只画侧边栏会话行（含搜索行），按钮上的角标与 CTA 位移删除 |
| **E meter** | 仪表计量 | 圆形图标按钮 / 主 CTA / 菜单项 | 图标按钮四角准星刻度；CTA 底部读数条 `scaleX(.06→1)`；菜单项左缘指示条淡入 | 图标按钮 `scale(.92)`；读数条与标签同色（`accent-ink`，压在按下态的加深底上） | 移除（主 CTA 已归信号箭头，读数条失去落点） |
| **F stamp** | 落印 | 批准/运行 · 拒绝/停止 · 装饰按钮 · 普通按钮 | 普通按钮 2px 信号色外框 | 批准类 −1.5° 落印（180ms）；拒绝类水平抖动；装饰按钮 `scale(.88)` | 移除（落印的过冲是六套里唯一的「回弹」观感，与官网无回弹语法相抵触） |

**发送按钮是唯一的例外：它不做任何动效、也不改圆角。** 这里踩过一个具体的坑：
直角化把它的 `999px` 圆角清零，而方案 A 的悬停 `border-radius: 6px` 又把它变成圆角矩形，
于是「一悬停就冒出一个方不方、圆不圆的倒角」（实测 rest `0px` → hover `6px`）。
现在 A-1 排除了它——与同段的圆形图标按钮同款处理。参考对象是官方 `/operator` 右侧那一列干员切换按钮
（[调研附录 C](notes/endfield-motion-research.md)）：那一列里**没有任何形变动效**，全部状态只由
`background-color .2s` 与 `transform .3s` 承担，选中/悬停都用 2px `#fffa00` 描边表达，底色走
`#383838 → #626262 → #282828` 三段灰阶。发送按钮曾经挂着一个「信号色箭头滑入」，它比参考对象更吵，
而且发送是高频动作、每次悬停都重放。现在它只保留全局的颜色过渡；`test/motion-check.js` 有一条断言
钉住「悬停/按下：无伪元素、无动画、无位移」。

**为什么当初是六套**：官网的动效只有两支手法（`clip-path` 揭示、`scaleX` 扫描），工业母题里真正被动画化的也只有这两支——所以「再多几套」不能靠堆关键帧，只能靠**换母题**：角标来自工程图纸的框选语法、读数条来自仪表面板、落印来自盖章。三者的共同点是**都不产生位移**，因此不会推挤相邻元素，也不会让密集列表在悬停时抖动。

**逐条来源**（哪些是复刻、哪些是推导——这一栏以前散落在注释里，现在集中写死）：

| 方案 | 手法来源 | 该手法在官网的**状态** |
| --- | --- | --- |
| **A signal** | 箭头滑入 | 官方按钮 hover 原文：`color` + `background-color` + `border-radius` 三件套 `.2s ease`，圆角确实是被动画的属性（2px→6px）。箭头形取自同一规则里的 `clip-path` 三角，但官方用**变形**、本主题用**位移 + 淡入**（因为两点间插值会自交）。**圆角软化未采用**：悬停瞬间方角变圆角违背「圆角全局恒定」（用户实测反馈），见下方分歧清单 |
| **B silent** | 无手法（只有颜色） | 官网 78 条 hover 里 34 条只换底色——这是官方的主流写法，不是凑数 |
| **C impact** | 硬阴影位移 | **推导**：官网按钮的阴影是软阴影 `drop-shadow(0 0 .25rem rgba(0,0,0,.25))`，4px 硬阴影是本主题的推导 |
| **D clamp** | 四角 L 形角标 + 左缘边条 | **半有据**：官方表格表头**确实**用位图角标（`th-deco-rt.svg` 等）与方括号装饰——所以形状符合官网视觉语法；但官方那些角标**全是静态的，没有任何动画**。把它做成「悬停淡入」是本主题推导 |
| **E meter** | `scaleX` 读数条 | **有据（技法）**：官网加载层的整屏黄条就是 `transform-origin:left` + `scaleX(0→1)`，并明确不写 `width`。读数条这个**视觉隐喻**（仪表面板）是推导，准星刻度也是推导 |
| **F stamp** | 落印 `@keyframes` | **推导**：官网 13 个关键帧只做旋转/闪烁/呼吸/`scaleX` 揭示，**没有任何一个是落印或过冲**；`endfield-stamp` 的 `1.06 → 0.99 → 1` 是本主题自创的观感 |

一句话：**动效语法（时长、缓动、`transition` 的位置、合成器友好的属性）是从官网 CSS 实测复刻的；六套「母题」里有四套是主题推导。** 后者不违规——但必须像这张表这样标出来，否则下一个人会以为官网也这么做。

**实测依据**（[官网动效调研](notes/endfield-motion-research.md)，一手 CSS 取数）：

- 官网 148 条动效声明里 **83.3% 的时长只有两档：`.2s` 与 `.3s`**；缓动 68.6% 是 `ease`，`ease-in` 与 `steps()` 各 **0** 次，自定义贝塞尔只 1 条且 y ≤ 1（**无回弹曲线**）→ 本主题 D–F 的时长取 `.18s–.22s`，缓动一律 y ≤ 1。
  > 注意区分两件事：**缓动不回弹**是照做的；但 `endfield-stamp` 的**关键帧数值**确实做了一次反向过冲（`1.06 → 0.99 → 1`，约 1%），那是刻意模拟「印章落纸后回弹一点」的观感——属于上面第 2 类「主题推导」，不是官网语法。
- 官网 **`transition` 从不挂在状态规则上**（124 个带 transition 的选择器里，含 `:hover/:active/:focus` 的为 0）→ 本主题的过渡声明同样全写在基础规则上，状态规则只写目标值。
- 官网按钮 hover 的配方是 `transition: color/background-color/border-radius .2s ease`，**圆角 2px→6px 是被动画的属性**。本主题试过这个「悬停圆角软化」后撤掉：它让倒角随悬停状态变化、且只作用于部分按钮（图标/发送按钮被排除）——「部分按钮、悬停时才变的不一致倒角」。**圆角全局恒定**：直角模式一律 0，圆角模式保持上游原样。

**与官网的四处有意分歧**（都写在这里，免得日后被当成「官网也这么做」）：

1. **官网 `prefers-reduced-motion` 出现 0 次、`:focus` 规则 0 条**（`:focus-visible` 仅 1 条）。本主题的焦点环与减效降级都是**主题自加**的：`reduce` 下位移/动画/揭示全部关掉，只保留颜色反馈（角标与箭头都不生成% 刻度、角标两个都不生成、落印不播放）。
2. **角标与读数条在官网是静态装饰**（`repeating-linear-gradient` 斜纹 4 处、角标全部静止）。把它们变成「悬停才出现」的动效是本主题的推导，不是复刻。
3. **官网在 hover 里动圆角（2px→6px），本主题不做**。圆角是「全局恒定」的属性：直角模式一律 0、圆角模式保持上游原样，不随悬停/按下变化（用户实测反馈定为准则）。同一条准则把 A-5 的左边框从设置页按钮上撤了下来：那些按钮原生带整圈 1px 边框，左边被压成 3px 透明条后上下边在左缘断开（02 背景/03 动画组实测反馈）；左边框只属于原生无边框的「行」（侧栏会话行、表格行）。
4. **官网在 28 处用 `@media(any-hover: hover)` 守卫悬停，本主题没有**。触屏上点按后悬停态会粘住（角标/箭头停在屏幕上）。这是**已知缺口**，不是「官网也这样」；要补的话应该只包住「揭示式」的 hover 规则，颜色反馈不必包。

### 背景纹理：官网 /operator 那一套

背景不是「深色底 + 一点噪点」，也不是整窗平铺——官网把每一层**锚定在内容区的一个部位**（[调研附录 D](notes/endfield-motion-research.md)），本主题逐条照搬这套锚定，映射到主内容列：

| 层 | 官方锚定 | 本主题落点 |
| --- | --- | --- |
| 工程网格 | `decoFlag`：clip-path 水平裁到中央内容列，mask 180°（上半实、50% 后淡出），`opacity:.05` | 会话根 `::before`：**颜色渐变自带 180° 淡出**，官方 SVG 当 alpha 遮罩只管形状；只画内容列的上半段 |
| 45° 斜纹 | `shallowBg`：**底部一条 32.8125rem 高的带**，mask 0°（底边最实、往上渐隐），`.75rem` 周期、`13.9512529279%/36.0487470721%` 停靠 | 会话根 `::after`：叠加层本身就是那条带（top/bottom 定界，不声明尺寸），单一 0° 遮罩复刻渐隐；窄视口把带高收到 45% |
| 右上波纹 | `backgroundDeco:before`：`right:0; top:0`，39.1875×26.3125rem / contain | standard 档的背景图层，钉内容列右上角 |
| 中下波纹带 | `decoTape`：`top:50%+3.8125rem`，13.5rem 高，白底 + 左缘 mask 渐隐 | standard 档的背景图层，照官方放中下部。官方的左缘 mask 在窄列里失效（图几乎塞满整列，顶边成了横贯全列的硬切线，实测行间跳变 11 灰阶），改用一条「同盒、顶部底色、往下 3.5rem 渐透明」的覆盖层把顶边揉掉——mask 的意图转了 90°，修后跳变 2.7 |
| 三色信号线 | `decoLine`：67.5rem 容器上的绝对停靠 11.25/22.5625rem → **紫:黄:绿 = 1:1:4（绿占 2/3）** | 设置页分组标题下。比例换算成百分比停靠（16.6667%/33.4259%），任何宽度下都是官方观感——照抄绝对 rem 会让三条色带在窄容器上几乎均分（实测反馈）。工作区顶部分划线曾短暂上过线，后按用户指示移除、回归应用原生 0.5px 分割线 |

**锚点是会话根，不是 `_centerCol`**——`_centerCol` 里面还有一层**不透明的** `wSkVaW_root`（`background:var(--dsw-alias-bg-base); height:100%`）。挂在 `_centerCol` 上的 `z-index:-1` 叠加层会画在那层不透明底**之下**、整段纹理无声消失（像素实测零变化）；挂到根上才真正落在「根底色之上、正文之下」。侧栏与外框不挂纹理；往 `_frame`/`_sidebarCol` 上铺等于整窗平铺，测试里有绊线专门防这个回归。

**水印共存是例外，且只在水印真挂 body 时**：选择器带 `:not(:has(> [data-endfield-watermark]))`——水印挂 body（hero 页）时隔离根会让整个根子树变成一个 z:auto 单元，被 body 级水印按 DOM 顺序压过（水印自己修过的那类 bug，见 `test/watermark-stacking.test.js` 头注）。此时网格/斜纹让位、波纹/光晕照常（背景图层不建层叠上下文）；水印关闭或在会话内时，hero 页也有完整底纹。这与水印自己的 `:has` 条件隔离是同一门派。另一个实测教训：**选择器不要求 root 是 centerCol 的直接子元素**——插槽挂载会有包装层，`>` 会整段静默失配（用户报「看不到底纹」的根因之一），所以用后代 + `[data-phase]`（只在 ConversationRoot 上出现，水印查找器用的同一钩子）。

四条实现要点，每条都是踩过才写下来的：

1. **官方网格 SVG 只能当遮罩**：路径只有 `stroke` 没有 `fill`（透明底 + 黑描边）。当背景图画不出东西；当不透明图画会把整面刷黑。所以走 `mask-image`，颜色另给（与水印徽标同一手法）。
2. **`url()` 不能当渐变色**：把 `--edge-tex-grid`（一个 `url(...)`）塞进 `linear-gradient()` 会让整条 `background-image` 在计算值阶段失效、解析成 `none`——实测一整叠图层无声消失。
3. **淡出不放进遮罩列表**：多张 mask 默认 `add`（并集），把「形状遮罩 + 渐隐遮罩」写在一起会得到整面色块。所以网格的渐隐放在**颜色渐变里**（一层遮罩只管形状），斜纹的渐隐用**单独一条 0° 遮罩**（它只有这一层遮罩）。
4. **叠加层必须压在内容之下**：`::before/::after` 用 `z-index:-1`，宿主 `isolation:isolate` 建层叠上下文——没有这一步，-1 的伪元素会落到列自己的背景后面（等于看不见）。第一版还把叠加层写成 `position:fixed; inset:0` 挂三个面，纹理盖住全窗——正是这次修掉的「整窗平铺」。

**装饰强度是量出来的**：网格/斜纹的 alpha 取官方那档（亮 5%/5%，暗 7%/6%），合成后对实际底面 **1.10–1.19:1**，落在与水印、hero 光晕同一条装饰区间（1.06–1.60:1）。`test/texture.test.js` 从样式表读 alpha 再算，不是复述数值。

**默认 `standard`**：三档 `off / subtle / standard`，出厂给完整版。三档都按**值**匹配（`data-endfield-texture='subtle'`/`'standard'`）——不按属性存在匹配，这样属性残留 `'off'` 值时也不会画（第一版按存在匹配，实测残留值时纹理照画）。`prefers-reduced-transparency: reduce` 与 `prefers-contrast: more` 下整段关闭（含两个叠加层的 `display:none`）；纹理不含任何动画。

**性能约束（都被 `test/perf-motion.test.js` 钉住）**

官网那篇调研给出的性能线索比视觉线索更硬：13 个关键帧里只有 4 种玩法，`transform` / `opacity` 是绝对主力，而它自己的黄条揭示**宁可写 `scaleX` 也不写 `width`**——因为 `width` 每帧都要重排重绘。这套主题照做，并且在浏览器里量过：

- **读数条用 `scaleX` 而不是 `width`**：元素按 100% 宽静态存在（栅格化一次），视觉宽度由 `transform: scaleX(.06 → 1)` 给出。动效测试同时断言「展开前后 `width` 不变」，防止有人改回去。
- **通用过渡只留颜色**（`background-color` / `color` / `border-color`）。`box-shadow`、`filter`、`width` 不进 transition——它们在悬停按下时本来只变一次，加过渡只会让每次悬停多跑一遍栅格化；`border-radius` 更贵（浏览器按「可能重排」处理），只留在方案 A 自己那条规则里。
- **菜单行指示条常态存在、悬停只切 `opacity`**：早先用 `content:'[' / ']'` 生成方括号，会在悬停时**生成文本节点**（文字布局）；改成既存的纯色渐变细条后，悬停只引起一次重绘。行内边距是静态值，不再有 `padding-left` 过渡（那会让悬停触发行重排）。
- **悬停才出现的几何一律预建**：角标/准星/指示条/左缘边条都在常态就有盒子，悬停只切 `opacity`（用 `@keyframes` + `fill-mode:both` 淡入，而不是 `transition`——本仓库实测 transition 在部分渲染路径上不触发）。这一条把 layout 从 8–29 ms/s 消到 **0.00 ms/s**：实测「`content` 只写在悬停规则里」是 29.2 ms/s，「`content` 在悬停、几何在常态」同样是 29.2 ms/s（代价来自伪元素在常态**是否已存在**，不是 `content` 写在哪），只有「常态生成 + 切 `opacity`」是 0.00。

实测（`node test/perf-motion.test.js`，无头 Chromium，420 个可交互元素、指针 1.6s 扫过 300 行）：

| 方案 | LayoutDuration | 主线程 | 帧 p95 / max | >32ms 帧 |
| --- | --- | --- | --- | --- |
| signal / impact / clamp / stamp | **0.00 ms/s** | 101–161 ms/s | 16.7 / 16.8 ms | 0% |
| **meter** | 2.5–3.2 ms/s | ~161 ms/s | 16.7 / 16.8 ms | 0% |
| silent（地板） | 0.00 ms/s | ~70 ms/s | 16.7 / 16.8 ms | 0% |

E meter 是唯一有残余的一档：把 24 个图标按钮的准星伪元素整条去掉，layout 就回到 0.00；只去掉它的渐变、`background-position` 或宿主 `position: relative` 都**没用**——代价来自伪元素**存在本身**（约 0.04ms/帧）。这个量级不构成流畅性问题（帧间隔 p95 与 >32ms 占比全绿），所以判据把 layout 预算定在 4 ms/s：既容得下它，又能在「悬停才生成几何」那类真正昂贵的写法上（16–29 ms/s）立刻报警。

**「悬停时才生成几何」是唯一真正的坑，而且它可以被彻底消掉。** 这一条推翻过一版设计：D 的角标最初写成「悬停时才 `content:''`」，量出 **13.4 ms/s** 的 layout（同一夹具、同一次运行、同一轮里 meter 的常态存在指示条是 0.00）；把几何挪到常态、悬停只切 `opacity` 之后，六个方案全部回到 **0.00 ms/s**。同样地，方案 A 的侧栏左缘边条如果是悬停时才加 `border-left`，代价是 **11.6 ms/s**；先在常态占一条 `3px solid transparent`、悬停只变色就是 0.00（impact 本来就是这么写的）。所以现在的做法是：**凡是悬停才出现的东西，都把它的盒子预先建好，只让颜色或透明度变化。**

另有三条第三方复现记录（`cross-verify`）：(1) 「悬停才生成盒子」的代价实测 **16.2 ms/s**（本文件早期写的 29.2 是同一夹具另一次运行的值，区间以 8–29 为准）；(2) 把角标的入场 `animation` 整个去掉，layout 反而翻倍（16.7 vs 8.8 ms/s）；(3) 早期「连注入 `!important` 也压不动」的说法**不成立**——`!important` 是有效的，真正压不动的是同等重要性下特异性更低的声明（基础规则 (0,5,2) 高于悬停规则 (0,4,2)，而动画/`!important` 都在它之上）。，只留一个角标也一样，`mask`/`z-index`/尺寸都无关——**变量是「盒子是否在悬停时才被创建」，不是动画本身**。因此判据写成绝对预算（layout ≤2 ms/s、主线程 ≤350 ms/s ≈ 每帧 ≤5.8ms），真正的「顺不顺」由帧间隔 p95 与 >32ms 帧占比负责。

另外两条实测约束：

- **停留不做事**：指针**停**在按钮上 1.6s 时六个方案 layout 都是 0.00 ms/s——代价只在指针**移动**时发生。
- **不用 `will-change`**：静态守卫断言动效段没有常态 `will-change`——在几百行列表上预建合成层是拿内存换一点点收益。
- **知道「预建盒子」的边界**：D 的角标占用了元素的 `::before`/`::after`，主题选择器（`body[attr]` 前缀，0,5,2）会盖过上游按类选择器写的自绘伪元素（0,1,1），**且从悬停扩展到了常态**。实测过（`motion-check` 有一条断言钉住这个行为），并且查过安装态 bundle：整个应用只有一处 `::after` 画在图标按钮上，而那类控件已被排除——所以这是**已记录的边界**，不是现存故障。将来上游若给方角按钮加 `::before` 纹样，clamp 模式下它会消失，届时应改由元素自身的 `background` 或子元素承载角标。

**实现约束（都被 `test/motion-check.js` 钉住）**：

- 所有颜色走既有变量：角标/刻度/指示条用 `--edge-accent-onpaper`（画在纸/面板上；暗色下侧栏行悬停底就是 accent，所以**亮暗分档**），**读数条用 `--edge-accent-ink`**——它压在强调色实心底上，必须与那个底配对，而不是与纸配对。这里踩过两次同一个坑：先用 `--edge-accent`（与底同色，1.00:1，完全看不见），再换 `--edge-accent-onpaper`（在亮黄/亮青两套配色里**等于** accent，1.00–1.51:1，依旧看不见）。两次都躲过了测试，因为 `--edge-accent-onpaper` 这个角色**从来没有被任何对比度断言覆盖过**——现在 `test/palette-contrast.test.js` 第 12 节专门守「读数条 × 强调底/加深底」，三套配色 **5.41–16.50:1**（accent 组下界 5.41 是终末地灰暗色，deep 组上界 13.60）。教训：加了新角色就要给它加断言，否则「有测试」只是错觉。
- 三套方案都以 `<body>` 属性为前缀，互斥生效；`off` 时一条规则都不命中。
- 上游按钮自带 `transition: none !important`，主题用的是 `!important` 覆盖与被限定作用域的选择器（图标/走纸按钮被排除在角标与准星之外——它们被恢复成圆形，在圆上放角标是错的）。
- 伪元素角标的前提是宿主 `position: relative`：主题自己补声明，不依赖上游。

## 六、直角化怎么实现

直角不是逐个组件改，而是**先全部清零，再恢复该圆的**：

```css
body:not(.theme-endfield-round) [class] { border-radius: 0 !important; }
body:not(.theme-endfield-round) [class*='avatar'],
body:not(.theme-endfield-round) [class*='spinner'],
body:not(.theme-endfield-round) [class*='dot'],
body:not(.theme-endfield-round) [class$='_iconButton'] { border-radius: 50% !important; }
```

用 `[class]` 而非 `*`，避免命中无类名的结构性节点；用 `body:not(.theme-endfield-round)` 作前缀，让「主题圆角」开关只是 `<body>` 上加减一个 class，不需要重新注册样式表。

## 七、配色切换是一个 class

整份样式表里所有强调色都读**调色板变量**，所以切换配色只是 `<body>` 上加减一个 class：不重新注册令牌层、不重算样式、无 JS 重绘。

这一点能成立依赖一个事实：**应用是把主题令牌写成 `<body>` 的行内样式的**（`dsh-client-ui-layout` 对每个令牌调 `body.style.setProperty`）。因此主题把 `--dsw-alias-brand-primary` 的暗色值声明为 `var(--edge-accent)`，该令牌就随 class 自动重解析。

配色切换后的实测像素占比（`test/verify-shots.js` 解码真实截图统计）：

| 截图 | 黄色像素 | 青色像素 |
| --- | --- | --- |
| 谷地黄 · 亮色 | **5.47%** | 0.44% |
| 武陵青 · 亮色 | 0.39% | **6.51%** |
| 谷地黄 · 暗色 | **2.51%** | 0.42% |
| 武陵青 · 暗色 | 0.34% | **5.40%** |

约 93% 的中性像素（纸底、墨字、边框）在两版之间基本不变——切换只动强调色。

## 八、可复用的几条经验

如果只带走几句话：

1. **颜色是量出来的，不是挑出来的。** 每个色值都对它实际落在的表面算过对比度；不达标的写法（哪怕看起来「就该是这个颜色」）一律改掉。
2. **同一个色在亮/暗模式下往往需要相反的处理。** 亮色下沉、暗色提亮，或者反过来，取决于该色相在那个亮度还剩多少余量。
3. **「装饰」和「前景」用两套标准。** 前景守 AA 4.5:1；装饰守「不抢眼但可见」的区间（约 1.06 ～ 1.6:1；水印为现存唯一装饰层）。
4. **主题令牌自身可以是 `var()` 引用。** 这是把「换配色」从一次重绘降级成一次 class 切换的关键。
5. **底色归主题、文字归应用 = 裂缝。** 只接管背景令牌而不接管前景，会造出「白字压在黄底上」这类 1.05:1 的不可见组合。改一个背景令牌时，要一起检查谁在上面写字。
